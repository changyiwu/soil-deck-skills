# SOIL 可編輯教學簡報

先完成教學判斷，再製作投影片。維持可編輯文字、圖形、表格、圖表與公式；只有主視覺或輔助素材需要點陣圖片。

## 工作模式

依請求選擇一種模式：

- `full`：將素材或主題製作成新簡報，依序執行六顆引擎。
- `diagnose`：檢查既有簡報，只回報問題與優先級；使用者要求修改時才改檔。
- `revise`：依已確認的診斷修改既有簡報，保留原有意圖與可編輯性。
- `style`：只產出可重複使用的風格與版型契約。

請求已清楚時直接選擇模式。只有缺少會改變教學設計的資訊時，才詢問教學對象、授課時間、學習成果或必須保留的內容；一次只問最關鍵的問題。

## 六顆引擎

1. **概念定位**：定義一個總概念、三個以內的子概念、常見誤解、帶走一句話與最小事實包。
2. **脈絡定位**：安排引起動機 → 維持注意 → 喚起行動；讓每一段都有清楚目的。
3. **頁面架構**：為每頁指定角色、學習任務、核心重點、語意關係與適合的版型。
4. **認知編修**：運用降雜訊、區塊化、增資訊、結構化、順脈絡與步驟化改善理解。
5. **風格建構**：建立色盤、字型、標題錨點、間距、視覺母題、資料圖表與圖片政策。
6. **簡報製作**：先做骨架與代表頁，再完成全稿；渲染、檢查、修正後交付。

完整輸出格式、頁面角色與判斷規則見 `references/soil-engines.md`。

## 製作新簡報

1. 讀取使用者素材，保留來源中的必要事實、術語、數字與引用。
2. 完成引擎 1–4，先產出頁面計畫；不要直接從原文逐段貼到投影片。
3. 完成引擎 5，選定視覺系統與三張代表頁：封面、標準內容頁、最複雜頁。
4. 使用可用的 Presentations 能力建立 `.pptx`。遵循 `references/powerpoint-production.md`。
5. 需要精確幾何時，使用原生可編輯圖形或依 `references/geometry-recipes.md` 建構；不要用裝飾插圖替代精確圖形。
6. 只有圖片能增加解釋價值時才使用內建 Imagegen。預設使用訂閱內建能力，不要求 API Key；除非使用者明確指定，不切換到外部 API 或 CLI。
7. 將簡報、渲染圖、蒙太奇與暫存驗證結果放在工作區的 `output/`。
8. 依 `references/diagnosis-and-validation.md` 完成視覺與教學 QA，再交付最終檔案。

## 診斷與修改既有簡報

1. 讀取文字結構並渲染每張投影片；同時看內容與畫面，不能只抽取文字。
2. 依頁面角色、脈絡、認知負荷、可讀性與視覺一致性列出問題。
3. 以高、中、低標示修改優先級，指出具體頁碼、原因與建議。
4. 若使用者只要求檢查，到此停止，不修改檔案。
5. 若使用者要求修改，保留原檔並輸出新檔；修改後重新渲染與驗證。

## 可編輯性政策

- 標題、內文、公式、表格、圖表、流程、幾何圖與標註預設使用原生可編輯元素。
- 不把整張投影片或大量正文烘焙成圖片。
- 圖片只承擔情境、人物、主視覺、材質或難以用原生元素表達的內容。
- 公式與數據需逐字核對；幾何比例與標記需視覺驗證。
- 每頁只保留一個主要教學重點，講者補充內容不要硬塞進畫面。

## 版面基準

- 使用 16:9 畫布與一致的安全邊界。
- 封面與關鍵行動頁可使用 48–72 pt 標題；一般標題使用 32–48 pt；正文通常不低於 18 pt。
- 同一份簡報固定標題錨點、色盤、字型層級、卡片語言與視覺母題。
- 依資訊關係選擇比較、流程、分類、關係圖、案例、數據、總結或行動版型，不把所有頁面做成條列清單。
- 使用者提供品牌或版型時優先遵循；沒有偏好時依教學內容建立克制、可讀的風格。

## 交付

交付前確認：

- SOIL 三段脈絡完整，常見誤解與帶走一句話已處理。
- 每頁角色、學習任務與核心重點一致。
- 沒有溢位、重疊、裁切、低對比或難以閱讀的文字。
- 可編輯元素仍可編輯；圖片、公式、圖表與幾何內容正確。
- 最終 `.pptx` 已重新渲染檢查，並回報絕對路徑。
