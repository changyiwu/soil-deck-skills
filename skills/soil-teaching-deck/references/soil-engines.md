# SOIL 六顆引擎

## 1. 概念定位

輸出一份概念定位稿：

- 總概念：用一句話說明這堂課真正要教什麼。
- 子概念：最多三項，彼此不重複。
- 常見誤解：列出學習者最可能犯的錯誤或直覺偏差。
- 帶走一句話：課後仍應記得的結論。
- 最小事實包：支撐理解所需的必要定義、證據、公式、數字與案例。
- 投影片／講述分工：畫面只放理解所需資訊，其餘留給口頭說明或備忘稿。

刪除與學習成果無關的旁支。資訊不足且涉及可驗證事實時，先查證或向使用者確認。

## 2. 脈絡定位

使用三段結構：

1. 引起動機：建立問題、衝突、情境或先備經驗。
2. 維持注意：逐步建立概念、關係、證據、例題與修正。
3. 喚起行動：要求判斷、應用、練習、反思或採取下一步。

10 頁簡報可先以 2／6／2 作為起點，再依內容調整。每一段都需標示目的、起點、轉折與結束狀態。

## 3. 頁面架構

每頁指定以下欄位：

```yaml
- page: 1
  soil_phase: hook
  role: question
  learning_task: 讓學生意識到既有直覺不足
  core_point: 一句核心訊息
  semantic_structure: focus
  layout: question_focus
  visible_text:
    title: 一個短標題
  speaker_only: 教師口頭補充
  visuals: []
  geometry: []
```

常用頁面角色：

| 角色 | 教學任務 | 常用版型 |
|---|---|---|
| 封面 | 建立主題與期待 | 主視覺＋短標題 |
| 問題 | 引發認知衝突 | 大問題＋單一焦點 |
| 迷思 | 對照錯誤與正確理解 | 雙欄或前後比較 |
| 概念 | 定義一個新觀念 | 定義＋例子 |
| 關係 | 說明層級、因果或組成 | 關係圖或流程 |
| 比較 | 找出關鍵差異 | 雙欄、矩陣或座標 |
| 步驟 | 建立程序 | 三至五步時間軸 |
| 案例 | 把概念放進情境 | 情境＋解讀 |
| 練習 | 讓學習者做判斷 | 題目＋提示／答案 |
| 數據 | 用證據支撐結論 | 大數字或單一圖表 |
| 總結 | 收攏核心概念 | 三個以內的帶走重點 |
| 行動 | 指定下一步 | 明確指令或選擇 |

每頁只承擔一項主要任務。變更版型是為了表達資訊關係，不是增加裝飾。

## 4. 認知編修

逐頁使用六項操作：

- 降雜訊：刪除無助理解的文字、裝飾、重複標籤與背景細節。
- 區塊化：把長內容切成可辨識的小單位。
- 增資訊：補上理解必須的例子、標籤、單位、證據或圖示。
- 結構化：用位置、群組、對齊、箭頭與層級顯示關係。
- 順脈絡：調整頁序與轉場，使前一頁自然支持下一頁。
- 步驟化：把複雜程序拆成可跟隨的有限步驟。

認知編修報告格式：

```markdown
### 第 N 頁：頁面標題
- 問題：具體描述
- 類型：降雜訊／區塊化／增資訊／結構化／順脈絡／步驟化
- 影響：說明學習者可能遇到的困難
- 建議：描述可直接執行的修改
- 優先級：高／中／低
```

## 5. 風格建構

建立簡潔的設計契約：

```yaml
style_id: teaching_style_v1
canvas: 16:9
palette:
  background: "#F7F4EC"
  primary: "#245B78"
  accent: "#E68A3F"
  text: "#172B3A"
typography:
  title: 粗體、清楚、短行
  body: 高可讀性繁體中文字型
shell:
  title_anchor: top_left
  safe_margin_in: 0.6
  page_number: true
image_policy:
  purpose: 只使用能增加解釋價值的圖片
chart_policy:
  purpose: 一張圖只回答一個問題
```

從使用者提供的參考簡報擷取配色、字型層級、標題錨點、卡片形狀、線條、留白、圖片風格與重複母題；不要複製無關的內容。

## 6. 簡報製作

分三輪進行：

1. 骨架：建立頁數、標題、頁面角色與主要元素。
2. 代表頁：完成封面、標準內容頁與最複雜頁，確認風格和密度。
3. 全稿與修正：完成其餘頁面，渲染後逐頁修正。

不要讓工具選擇反過來決定教學設計。先確定學習任務與資訊關係，再選擇圖形、圖表、圖片或版型。
